# RADAR Master Playbook — Phase 2 Build (GitHub Version)

Welcome team! The GitHub repository is officially live, and the architecture boundaries have been created. We are building an autonomous agent over the next 10 days. Since we are a 4-person team "vibe coding" from home, we are using a **Contract-Based Folder Architecture**.

**Golden Rule:** You are strictly forbidden from modifying any file outside of your assigned folder. If you edit code outside your folder, your Pull Request will be instantly rejected.

---

## 🏗️ Repository Architecture
The repository has been initialized with the following structure:
```text
radar_project/
├── main.py                      <-- (Member 1 ONLY)
├── contracts/
│   ├── incoming_papers.json     <-- What Member 2 must generate
│   └── pending_actions.json     <-- What Member 3 generates & Member 4 reads
├── data/
│   └── repo_context.md          <-- Example dummy data describing repo goals
├── fetchers/                    <-- Member 2's workspace
├── brain/                       <-- Member 3's workspace
└── outputs/                     <-- Member 4's workspace
```

## 👩‍💻 Role Assignments & Tasks (Phase 2 - Milestone 1)

### 👑 Member 1: The PR Reviewer & Integrator
**Assigned Folder:** Root Directory (`/`)
**Job:** You manage the GitHub repo and review Pull Requests. You do NOT write the individual scripts. You review them for quality and ensure they output the data exactly as specified in the `/contracts` folder. Finally, you write `main.py` to glue the scripts together.

### 🕵️‍♂️ Member 2: The Data Harvester (Inputs)
**Assigned Folder:** `/fetchers`
**Task:** Build a standalone Python script designed to query ArXiv (or Semantic Scholar) for the latest research papers matching a topic (e.g., "on-device AI").
**The Contract (IMPORTANT):** Your script must output its data by overwriting `contracts/incoming_papers.json`. Open that JSON file in the repository to see exactly what fields your logic must create (`title`, `abstract`, `url`, `authors`, `source`).
> **AI Prompt to use:** *"Write a Python script that searches the ArXiv API for 5 recent papers containing the keyword 'neural networks'. Save the extracted data into a JSON file located at `../contracts/incoming_papers.json`. Format the JSON fields to exactly match this structure: [paste the structure from the contract]."*

### 🧠 Member 3: The Threat & Memory Engine
**Assigned Folder:** `/brain`
**Task:** Build the LLM processing logic using the Google Gemini 1.5 API. 
**The Contract (IMPORTANT):** Your script assumes Member 2 has done their job. You just need to write a script that opens and reads `contracts/incoming_papers.json` and compares the abstracts against the `data/repo_context.md` file. Find papers with very high relevance to our goals. Save your output by overwriting `contracts/pending_actions.json` exactly as structured in the repo.
> **AI Prompt to use:** *"Write a Python script using the google-generativeai API. The script should read two files: a JSON list of papers at `../contracts/incoming_papers.json`, and a Markdown context file at `../data/repo_context.md`. Ask Gemini to find exactly one highly relevant paper matching the goals in the Markdown. Save the result as a new JSON file at `../contracts/pending_actions.json` matching this exact structure: [paste the structure from the contract]."*

### 📡 Member 4: The Communicator (Outputs)
**Assigned Folder:** `/outputs`
**Task:** Build the messaging layers linking our results to the real world.
**The Contract (IMPORTANT):** You just need to process Member 3's output. Write a script that reads the `contracts/pending_actions.json` file. Then, use the `python-telegram-bot` standard library to send the `reason` and `action` to a Telegram chat. 
> **AI Prompt to use:** *"Write a Python script that reads an alert generated by an LLM at `../contracts/pending_actions.json`. Iterate through the alerts in the JSON and use the `python-telegram-bot` and `asyncio` libraries to send a clean Markdown-formatted alert to a Telegram channel. Just write the standalone script, no complex web servers."*

## 🚦 Required Git Workflow 
We will have **zero merge conflicts** if everyone works sequentially using the following rules:

1. **Clone the Repo:** `git clone https://github.com/Chakrika6/SAMSUNG_PRISM.git`
2. **Create Your Branch:** `git checkout -b feature/your-folder-name`
3. **Vibe Code & Run Locally:** Run your script from your command line to make sure it properly reads/writes the `.json` contract files.
4. **Push:** `git add .` -> `git commit -m "added basic script"` -> `git push -u origin feature/your-folder-name`.
5. **Open a PR:** Go to GitHub.com and open a Pull Request. **Member 1 will review it.**

Happy hacking! 🚀
